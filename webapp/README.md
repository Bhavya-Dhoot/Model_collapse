# webapp — React version, charts by bklit UI

A hosted-web companion to the paper, built with Vite + React + Tailwind v4 and
[bklit UI](https://ui.bklit.com) charts installed through the shadcn registry.

```bash
cd webapp
npm install
npm run dev      # http://localhost:5173
npm run build    # -> dist/
```

## This does not replace the offline dashboard

`demo/dashboard.html` stays the file you put on a projector: one double-clickable
page, no server, no network. This app cannot be that — it is a bundled React
build (~586 KB JS), ES modules are blocked over `file://`, and bklit ships React
source rather than a CDN bundle. The two are complementary:

| | `demo/dashboard.html` | `webapp/` |
|---|---|---|
| Opens by double-click, offline | yes | no (needs a server) |
| Charts | hand-drawn SVG (`demo/lib/chart.js`) | bklit UI |
| Self-running presentation mode | yes | no |
| Best for | presenting in a room | hosting a link |

## Data

`src/data.json` is copied from `demo/data.json` by `scripts/sync-data.mjs`,
which runs automatically on `predev` and `prebuild`. That file is generated by
`code/export_dashboard_data.py` from `results/main.csv` using the same
estimators as the paper's figure scripts, so the webapp, the offline dashboard
and the paper cannot drift apart. `src/data.json` is gitignored — it is a build
artifact, not a source.

## Two decisions worth knowing

**Bar charts, not line charts.** bklit's `LineChart` and `LiveLineChart` are
time-series components: they coerce x through `new Date()` and format ticks with
`Intl.DateTimeFormat`, with no formatter override. Our x-axes are generation,
α and n — numeric, not temporal — so a line chart would label "generation 3" as
a date. `BarChart` is genuinely categorical (`xDataKey`), which is correct for
every discrete grid in this paper, so all charts here are bar charts.

**The chart palette is not bklit's default.** bklit's own skill documents that
the stock `--chart-1..5` fail palette validation — in light mode `--chart-4` and
`--chart-5` sit 7.4 ΔE apart against a floor of 15, so adjacent series are
near-indistinguishable. `src/index.css` declares the corrected, separately
validated light and dark sets instead. Semantic status colours
(`--status-good` / `--status-bad`) are kept out of the categorical ramp.

## Motion

Native scroll is the only scroll authority — no smooth-scroll library and no
scroll-linked scrubbing. `motion/react` (already a bklit peer dependency) drives
two things only: section entrances, which fire once from a visible resting state
rather than parking content at zero opacity, and the mechanism animation. That
animation is driven by the paper's own recursion, so the fidelity bar shows the
real trajectory for the chosen α and n rather than an eased decoration.
`useReducedMotion` is a designed branch: particles stop, the loop still advances.
